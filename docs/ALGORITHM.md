# 算法说明（`adaptive-v2`）

本文说明作息调整算法 `adaptive-v2` 的规则、常量与工程取舍。目标作息与历史依据、步长曲线、
前移/后移不对称、三餐锚点、偏离三档、计划快照与达标率口径都在这里；每条规则的文献出处指向
[REFERENCES.md](REFERENCES.md) 的条目编号。接口字段与请求方式见 [API.md](API.md)。

> 一句话概括：**用“每天一小步、前移比后移更保守”的方式把作息推到目标点，三餐只作为可执行的
> 节律锚点而非相位杠杆，用户偏离计划时按偏离幅度分档处理，所有建议都以快照形式留痕。**

## 1. 目标作息与历史依据

- **目标来源有两种**：用户自定义目标（`/api/settings/target` 设置 `target_sleep_time` /
  `target_wake_time`，两个时间必须同时设置或同时清空），或系统按历史记录推断的默认目标。
  响应里的 `source` 字段会标注 `custom_target` 或 `system`。
- **系统目标是“统计规律”不是“个体处方”**：先取最近一段时间的入睡/起床中位数作为基准线
  （`basis` 字段给出参与统计的样本天数与派生值），再向更健康的方向收敛。样本不足时会缩短
  计划天数并给出 `advice.notice.*` 提示（例如计划被截短需要用户确认的那条）。
- **依据**：群体统计显示成人睡眠时长与就寝时间的规律，以及相位前移训练的有效速率区间
  —— 见 [REFERENCES.md](REFERENCES.md) 的 Eastman 2005（相位前移速率）、以及睡眠时长/就寝时间的
  人群统计条目。**前移速率有文献支撑，具体到“用户该几点睡”是工程推断值。**

## 2. 天数与步长曲线 `STEP_CURVE`

计划默认按“把基准线推到目标点需要多少天”计算（`days` 可被请求参数覆盖，范围 1–30）。
每天只移动一小步，并且**越接近目标步子越小**，避免最后一天过冲：

| 阶段（按剩余待移动量） | 每天步长上限 | 说明 |
| --- | --- | --- |
| 开头（离目标最远） | 大步长上限（`fast` 档） | 先快，先把明显不合理的作息拉回来 |
| 中段 | 递减 | 每前进一段，上限按曲线下降 |
| 收尾（接近目标） | 小步长上限（`slow` 档） | 后缓，避免过冲与反弹 |

- 曲线实现在 `backend/app/services/advice.py`，常量集中在 `STEP_CURVE`；返回体 `steps` 字段
  会带出每一段的上限与当天实际步长（`DayPlan.step_minutes`、`shift_sleep_minutes`、
  `shift_wake_minutes`）。
- **单调性与落地**：步长上限随进程递减，且累计移动量必须在计划最后一天**正好落在目标点**
  （不许留在半路，也不许超过）。这两条都有单元测试守着
  （`tests/test_advice_engine.py::test_step_curve_is_decreasing_and_lands_on_target`、
  `::test_step_profile_respects_caps_and_front_loads`）。
- 请求参数 `mode` 只有 `fast` / `slow` 两种进度档，用来在“尽快调整”和“温和调整”之间切换，
  不会改变目标点，只改变步子分配。

## 3. 前移 / 后移不对称

- **推迟（睡得比目标晚 → 往后挪）**的上限比**前移（往早挪）**宽松。原因是相位前移受内在
  昼夜节律周期（略长于 24 小时）抵抗，前移过快会出现入睡困难与睡眠效率下降；推迟顺应节律，
  代价小得多。
- 硬约束（有文献支撑）：**前移每天不超过 45 分钟**。依据是 Eastman 2005 的对照结果：
  1 小时/天约等于实际 30 分钟/天的有效前移，2 小时/天约 36 分钟/天并已出现睡眠效率下降
  —— 见 [REFERENCES.md](REFERENCES.md) 的 Eastman 2005 条目。
- 单元测试 `::test_delay_cap_is_looser_than_advance` 断言“推迟上限严格大于前移上限”，
  防止后来的人把两条上限改成一样。

## 4. 三餐锚点窗口

三餐不是相位杠杆（2025 年综述没有任何“进餐移动昼夜相位”的证据），但固定时间的进餐是**可执行
的节律锚点**，所以算法给出建议窗口，并且用户可以逐餐开关
（`meal_breakfast` / `meal_lunch` / `meal_dinner`）：

| 餐次 | 窗口（相对锚点） | 锚点 | 说明 |
| --- | --- | --- | --- |
| 早餐 | 起床后 **15–30** 分钟 | 起床 | 窗口起点即 `best_time` |
| 午餐 | 窗口长 **120** 分钟，起点取早餐与晚餐的**中点**再提前 60 分钟 | 两端（`both`） | 再夹进 [起床+120, 晚餐−240] 分钟；受“连续未吃早餐”规则前移（见下节） |
| 晚餐 | 窗口长 **90** 分钟，起点为睡前 **270** 分钟（4.5 小时） | 入睡 | 与睡眠锚点挂钩，不跟起床时间一起平移 |

- **午餐为什么取中点**：早先午餐锚在“起床 + 180 分钟”，白天越长，午餐与晚餐之间就拉得越开
  —— 06:00 起、01:00 睡（白天 19 小时）的人午餐 09:00、晚餐 21:30，间隔 **12.5 小时**；
  改成取早餐与晚餐的中点后，同一作息的间隔收敛到 7.6 小时左右。
- **整体提前 1 小时**：中点与睡眠锚点算完后，午餐与晚餐一起前移 `MEAL_ADVANCE_MIN = 60` 分钟，
  让饭点整体靠前（晚餐从“睡前 3.5 小时”变成“睡前 4.5 小时”），吃完还留有活动时间。
- **现实作息窗口（就近靠拢）**：作息正常时，饭点不该继续跟着极端时刻线性漂移，而要贴回社会时钟：

  | 条件 | 约束 | 常量 |
  | --- | --- | --- |
  | 起床 ≤ **15:00** | 午餐就近靠拢进 **11:00–15:00** | `NORMAL_WAKE_UNTIL` / `LUNCH_NORMAL_WINDOW` |
  | 入睡不晚于次日 **06:00**（或当天 17:00 之后，都算夜里睡） | 晚餐就近靠拢进 **17:00–22:00** | `NORMAL_SLEEP_UNTIL` / `DINNER_NORMAL_WINDOW` |

  “就近靠拢”= **落在窗口外才夹回最近的边界，窗口内的取值原样保留**，因此不会把本来合理的
  饭点挪走；作息一旦越界（15:00 之后起床、或 06:00–17:00 之间补觉），这一步整体跳过，
  直接沿用上一步的相对锚点结果 —— 极端作息本来就不该硬套社会时钟。
  实测（改进后）：07:00 起 / 23:00 睡 → 早餐 07:15、午餐 **11:52**、晚餐 **18:30**；
  06:00 起 / 01:00 睡 → 06:15 / **12:22** / **20:30**；09:00 起 / 02:00 睡 → 09:15 / **14:22** / **21:30**。
- **保序优先于窗口**：午餐必须在早餐之后、晚餐之前，晚餐还要留在睡前 2 小时之外。窗口与极端作息
  打架时（例如 14:50 起床却要求 11:00 吃午饭）以顺序为准，这一条写在 `_meal_times()` 的第 ③ 步。
- 响应里每餐是 `MealPlan`：`enabled`、`best_time`（等于窗口起点，兼容字段 `time`）、
  `window_start`、`window_end`、`anchor`（`wake` / `sleep` / `both`）、`shifted_minutes`（因未吃早餐
  前移的分钟数）、`bar_minutes`（时间图上的条长，仅视觉）、`note`（i18n 键）。
- **“起床后 X 分钟进食”这类钟点窗口在文献里并不存在**，它们是工程默认值；文献只支持
  “三餐作为节律锚点、不做相位移动”这一条，见 [REFERENCES.md](REFERENCES.md) 的 2025 年综述条目。

## 5. 午餐前移规则与连续未吃早餐计数

- 用 `POST /api/advice/checkin`（`meal` + `eaten`，可选 `date` 与 `refused`）记录“这一餐吃了没有”；
  记录会写回当天的睡眠记录。每餐的状态因此有四种：`eaten` / `skipped` / `refused` / `unknown`。
- **连续未吃早餐的天数**（`streak`）达到阈值后，午餐建议开始前移：前移量按 streak 递增
  （60 / 90 / 120 分钟），结果体现在 `MealPlan.shifted_minutes` 上。下限有两个：“不早于起床后
  2 小时”与社会时钟窗口的起点 **11:00**（作息正常时），所以前移在窗口里能走多少走多少。
- **“不想吃早餐”**（`meal="breakfast"` + `eaten=false` + `refused=true`）：与“跳过”一样计入
  连续未吃早餐，并且**当天的午餐与晚餐一起提前 60 分钟**（`REFUSED_BREAKFAST_SHIFT`）——
  晚餐提前 60，午餐再因为“取中点”跟着往前 30，所以阶梯从零起步时实测午餐共提前 **90** 分钟；
  若午餐已贴到窗口起点（11:00）或起床后 2 小时的下限，则实际位移相应变小。规则只作用于
  计划第一行（今天），明天起的建议不变。
- “不想吃”不重写已保存的计划快照，而是在读取时叠加（`apply_refused_breakfast_overlay()`）：
  否则 `plan_meta.replans`（“已重算 N 次”）会被打卡动作悄悄推高，历史计划也会被改写。
  点“已吃”即撤销（同一行 `refused` 写回 `false`）。
- **文案约束**：带参数的句子（`{streak}` / `{shift}`）一律由前端用数字字段拼（`tp()`），后端
  只返回不带参数的文案键 —— 否则页面上会原样显示 `{streak}`。
- 测试：`::test_lunch_shifts_earlier_when_breakfast_skipped`、
  `::test_lunch_midpoint_keeps_gaps_reasonable_on_long_days`、
  `::test_checkin_eaten_true_writes_back`、`::test_refused_breakfast_pulls_today_meals_earlier`。

## 6. 偏离三档

“当前计划”是一份快照；用户实际作息与快照对比得到偏离分钟数（取绝对值），分三档处理：

| 偏离幅度 | 处理方式 | 理由 |
| --- | --- | --- |
| **≤ 30 分钟** | 静默接受，不提示、不重算 | 属于正常波动，提示只会造成噪声 |
| **30–90 分钟** | 静默重算：自动把后续计划顺延/前移 | 已经偏离但仍属“同一天”，直接修正计划更省事 |
| **> 90 分钟** | 弹窗让用户选策略（`postpone` / `recompute` / `keep`） | 偏离足够大，必须由用户决定是顺延、重算还是保持原计划 |

- 静默重算**每天最多一次**（防止用户来回改动导致计划被反复重排），见
  `::test_auto_recompute_only_once_per_day`。
- 分档判定见 `::test_deviation_levels`；用户选择后走 `POST /api/advice/replan`，
  `strategy` 三选一，返回新的计划与 `plan_meta`。

## 7. 计划快照与重算

- 生成建议时默认 `save: true`，把当天的计划落库成**快照**（`plan_id` / `plan_meta.saved`），
  之后的偏离判定、达标率统计都以快照为基准，而不是每次重新计算。
- `GET /api/advice/plan` 取当前快照；`POST /api/advice/replan` 触发重算并写新快照；
  `plan_meta` 记录 `start_date`、`target_date`、`postponed_days`、`replans`、`saved`。
- 重算不会“抹掉历史”：快照是追加的，因此“当时建议了什么、后来改了什么”可追溯。
- 测试：`::test_plan_snapshot_deviation_and_replan`。

## 8. 达标率与连续天数口径

- **达标** = 当天实际入睡/起床落在快照给出的容差内（容差与偏离分档同源）。
- **未记录不计入**：没有记录的那天既不记为达标，也不记为不达标，分母里直接排除
  —— 见 `::test_adherence_ignores_unrecorded_days`。
- **不中断**：连续达标天数（streak）只被“明确的不达标”打断，缺记录的日子不打断连续。
  这样偶尔忘记记录不会让用户看到“连续清零”。
- 统计结果用于建议页的达标率展示，字段随建议响应一起返回。

## 9. 24 小时时间图的数据结构与跨零点处理

- 数据结构（`timeline` 字段）：

  ```json
  {
    "axis_start": "18:00",
    "axis_end": "18:00",
    "span_minutes": 1440,
    "sleep_label": "23:30 → 07:10",
    "sleep_minutes": 460,
    "items": [
      {"kind": "sleep", "start": "23:30", "end": "07:10", "minutes": 460},
      {"kind": "meal", "meal": "breakfast", "start": "07:25", "end": "07:40", "minutes": 15}
    ]
  }
  ```

- **跨零点处理**：睡眠区间通常跨过 00:00，所以时间轴不是 00:00–24:00，而是以“当天的入睡时刻”
  为轴起点向后展 24 小时（`axis_start` → `axis_end`，`span_minutes` 恒为 1440）。区间条按
  “相对轴起点的分钟偏移 + 长度”绘制，因此跨零点只需一次取模，不需要为跨天做特例。
- 每个 `DayPlan` 也有自己的 `timeline`（每日方案里的迷你时间图），结构与顶层一致。
- 测试：`::test_timeline_wraps_around_midnight`。前端绘制逻辑在 `frontend/shared/timeline.js`
  （`frontend/shared/README` 不适用，直接看该文件）；窄屏会切换成纵向时间图。
- 视觉约束：时间图的条不能压到时间刻度或“睡眠/早餐/午餐/晚餐”图例上，本地验收会用
  `getBoundingClientRect` 判定相交，任何相交都算失败。

## 10. 工程默认值一览

| 常量 / 默认值 | 取值 | 含义与出处 |
| --- | --- | --- |
| 引擎代号 | `adaptive-v2` | 响应 `engine` 字段固定为该值 |
| 计划天数 | 按需推算，可取 1–30 | 请求参数 `days` 覆盖；样本不足时截短并提示 |
| 进度档 | `fast`（默认）/ `slow` | 请求参数 `mode`，只影响步子分配 |
| 步长曲线 | `STEP_CURVE` 分段上限 | 先快后缓，逐步递减；见第 2 节 |
| 前移上限 | **45 分钟/天** | 有文献支撑（Eastman 2005） |
| 推迟上限 | 严格大于前移上限 | 顺应节律，代价小；`::test_delay_cap_is_looser_than_advance` |
| 早餐窗口 | 起床后 **15–30** 分钟 | 工程默认值（文献无钟点窗口） |
| 午餐起点 | 早餐与晚餐的**中点**，整体提前 **60** 分钟，夹进 [起床+120, 晚餐−240] 分钟 | 工程默认值；早先锚在“起床+180”，白天越长间隔越大（19 小时白天可达 12.5 小时），故改为取中点 |
| 午餐窗口长 | **120** 分钟 | 与早餐/晚餐窗口等长口径一致，可因连续未吃早餐前移 |
| 晚餐窗口 | 窗口长 **90** 分钟，起点为睡前 **270** 分钟（3.5 小时 + 整体提前 1 小时） | 工程默认值，锚在睡眠侧 |
| 现实窗口·午餐 | 起床 ≤ **15:00** → 午餐就近靠拢进 **11:00–15:00** | `NORMAL_WAKE_UNTIL` / `LUNCH_NORMAL_WINDOW`，社会时钟参考 |
| 现实窗口·晚餐 | 入睡不晚于次日 **06:00**（或当天 17:00 之后）→ 晚餐就近靠拢进 **17:00–22:00** | `NORMAL_SLEEP_UNTIL` / `DINNER_NORMAL_WINDOW`，越界则跳过窗口 |
| 三餐开关 | `meal_breakfast` / `meal_lunch` / `meal_dinner` | 用户级设置（`/api/settings`），默认开启 |
| 偏离静默阈值 | **≤ 30** 分钟 | 静默接受，不提示 |
| 偏离重算区间 | **30–90** 分钟 | 静默重算，每天最多一次 |
| 偏离弹窗阈值 | **> 90** 分钟 | 交由用户在 `postpone` / `recompute` / `keep` 中选择 |
| 时间图跨度 | 1440 分钟 | 以当天入睡时刻为轴起点，支持跨零点 |
| 快照保存 | `save: true`（默认） | 生成建议即落库，偏离与达标率都以快照为基准 |
| 达标率分母 | 仅“有记录”的天 | 未记录既不算达标也不算不达标，不打断连续 |
| 写入冷却 | 10 秒/用户 | 配置项 `SSP_WRITE_COOLDOWN_SECONDS`，命中返回 429 |
| 记录保留 | 6 个月 | 定时清理任务，见 [DEPLOYMENT.md](DEPLOYMENT.md) |

**文献支撑 vs 工程默认值的边界**：只有两条有文献支撑 —— 相位移动速率（前移 45 分钟/天）与
“三餐只做节律锚点、不作为相位杠杆”。其余常量（起床后 15 分钟吃早餐、午餐取中点再提前 1 小时、
现实作息窗口 11:00–15:00 / 17:00–22:00、步长曲线形状、偏离分档阈值）都是工程默认值，
可按实际使用反馈调整，调整时同步更新本表与
[tests/test_advice_engine.py](../tests/test_advice_engine.py)。
